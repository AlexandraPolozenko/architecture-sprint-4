**Планирование: анализ, идентификация проблем и поиск решений**


**Существующие и потенциальные проблемы:**
- У всех приложений по одному инстансу (система будет недоступна, если дц выйдет из строя, сложнее масштабировать нагрузку)
- У всех бд по одному инстансу (аналогично)
- CRM API ходит напряму в бд Shop (антипаттерн, лучше, чтобы каждый микросервис обращался только к своей бд)
- Нет пагинации на странице списка заказов
- Не настроено кэширование нигде (соответственно более долгое время отклика для клиентов, особенно проблематично для рассчета стоимости украшений)
- Не настроены механизмы circuit breaker и backpressure (при недоступности одной из частей системы, вся система будет отдавать ошибки)
- Не настроены мониторинг, сбор метрик, логирование и трейcинг (на данный момент сложнее диагностировать, какие куски проблемные)
- Тестирование только ручное, соответсвенно релизный цикл замедляется
- Общее апи для сайта и для внешних клиентов (невозможно сделать обратнонесовместимые изменения для использования внутри системы)
- Синхронный поход в апи рассчета стоимости заказа (долгая операция)
- Нет проверок на антифрод (например в ситуации, когда один пользователь отправит на рассчет тысячи изделий одновременно) и лимитера запросов


**Инициативы по улучшению:**

- Добавить инстансы бд
- Разработать api на стороне Shop для CRM (чтобы получать необходимую инфорацию из ShopDB). Либо отдельные бд для Shop и СRM (конкретно тут указано именно апи, т к без описания реализации кажется, что микросервиса оперируют похожим сущностями и поддерживтаь согласованность статусов между разными бд будет сложнее)
- Реализовать пагинацию на странице заказов (и в любых других апи, где выгружаются массивы данных)
- Реализовать кэширование стоимости заказа для файла
- Реализовать кэширование/сохранение в бд предподсчитанной стоимости (переработать алгоритм рассчета стоимости так, чтобы он мог базироваться на предыдущих рассчетах, при изменении, например, небольшой детали украшения)
- Реализовать кэширование для ShopDB (например данные по заказу, т к статусы, за исключением новых заказов, меняются не часто)

- Реализовать circuit breaker (на случаи недоступности каждого из микросервисов)
- Реализовать backpressure для чтения/записи из очереди
- Реализовать трейсинг
- Реализовать распределенное логирование
- Реализовать сбор метрик
- Реализовать мониторинг и алерты на критичные проблемы
- Реализовать автотесты и добавить их в процесс ci/cd
- Реализовать апи для внешних клиентов
- Реализовать асинхронное получение стоимости заказа
- Реализовать бизнесовые проверки на антифрод
- Реализовать рейт лимитер и антиробот
- Реализовать дедубликацию всех запросов


**Приоритеты:**
1. Асинхронный рассчет стоимости заказа и его сохранение в бд
Т к на данный момент нужно как можно быстрее стабилизировать систему (клиенты уже отказываются от работы с приложением), то необходимо начать с наиболее узкого места, а именно с самой долгой операции. Это даст быстрый и интуитивно заметный результат.

2. Дополнительные инстансы для приложений и бд
Нагрузка постоянно увеличивается (есть сигналы, что система уже с ней не справляется), хочется добавить мощностей системе, чтобы избавиться от проблем с зависанием в моменте и выиграть время для остальных оптимизаций.

3. Реализовать мониторинг, трейсинг и логиргование
Эчто позволит раздебажить проблемы с потерей заказов и приоритезировать остальные доработки.

- Реализовано отдельное апи в shop или бд для crm
