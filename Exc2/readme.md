**Выбор и настройка мониторинга в системе**


**Мотивация:**
Мониторинг необходим, т к система уже не справляется с повышением нагрузки и увеличением числа пользоватлей. Мониторинг позволит отлавливать 
проблемы быстрее, чем о них сообщат пользователи системы, к тому же мониторинг позволит раньше узнавать о пробелмах в релизе, что ускорит доставку 
бизнес-ценности. Во время рефакторинга архитектуры мониторинг позволит быстрее найти узкие места и оптимизировать потребление ресурсов.
Кроме того, мониторинг и актуальные метрики помогут узнавать ценные бизнес-инсайты и рост/падение бизнес-показателей после выпуска новых фичей, в 
в будущем упростят проведение АБ-экспериментов.


**Выбор подхода к мониторингу:**
RED - для микросервисов системы (shop, mes, crm), чтобы отслеживать работу приложения для конечных пользователей системы
USE - для ресурсов баз данных и приложений (использование cpu, ram и пр), особенно для mes, т к на нем самые сложные вычислительные операции


**Список метрик:**
- Number of dead-letter-exchange letters in RabbitMQ
Понимать, сколько сообщений не успеваем обработать
- Number of message in flight in RabbitMQ
Понимать, на каких потребителях задержки и проблемы, ярлыки: читатель
- Number of requests (RPS) per user for internet shop API, CRM API, MES API
Понимать нагрузку на апи и посмотреть пороги для защиты от ddos, ярлыки: эндпоинт, http-метод
- CPU % for shop API, CRM API, MES API
Отслеживать, когда сервис не справляется с нагрузкой
- Memory Utilisation for shop API, CRM API, MES API, shop db instance, MES db instance
Отслеживать потребление ресурсов, необходимость долить ресурсов/оптимизировать работу приложения и пр
- Response time (latency) for shop API, CRM API, MES API
Понимать задержки для потребителей апи (конечных пользователей), где необходимо оптимизировать работу приложения, ярлыки: эндпоинт, http-метод
- Size of S3 storage
Потребление ресурсов хранлища файлов, отслеживать, когда нужно добавить механизм очистки, доливать еще ресурсов
- Number of HTTP 200/500 for shop API, CRM API, MES API
Понимать процент ошибок в работе апи, ярлыки: эндпоинт, http-метод


**План действий:**
1. Определить необходимые метрики (по сути - пункт выше)
2. Настроить Prometheus для микросервисов.
3. Настроить экспортеры метрик для баз данных и RabbitMQ.
4. Настроить Grafana для визуализации метрик.
5. Реализовать дашборды для ключевых метрик (метрики апи, потребление ресурсов, состояние RabbitMQ).
6. Настроить алерты на критичные метрики
